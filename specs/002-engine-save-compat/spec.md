# Feature Specification: 引擎存档路径兼容

**Feature Branch**: `002-engine-save-compat`  
**Created**: 2026-11-14  
**Status**: Draft  
**Input**: 按已确认的推荐方案，为 macOS 下运行 Windows Electron 游戏新增引擎存档路径适配；保留游戏原始入口和游戏包，明确存档位置，安全处理两处旧存档。

## Clarifications

### Session 2026-11-14

- Q: 开启存档兼容后，游戏原有的清空存档、刷新和重新加载功能是否保留？ → A: B，必须保留；完成适配及相应测试后才能交付，不能以禁用这些操作作为首期方案。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 使用游戏目录中的旧存档续玩 (Priority: P1)

玩家启用受支持引擎的存档兼容后，能够看到实际存档位置，读取游戏安装目录中已有的文件存档，并将后续进度保存在同一位置。

**Why this priority**: 当前游戏可以启动，但部分引擎按 macOS 应用包结构计算路径，无法读取 Windows 游戏目录中的原有进度。

**Independent Test**: 使用受支持引擎行为的合成游戏与隔离存档，完成读取旧进度、保存新进度、退出和重新启动的闭环。

**Acceptance Scenarios**:

1. **Given** 游戏停止、引擎已识别且只有安装目录根部有有效存档，**When** 玩家确认启用兼容及该位置，**Then** 游戏读取该存档，界面显示实际存档目录，后续保存与重新启动均使用该目录。
2. **Given** 两个候选目录均无存档，**When** 玩家确认启用兼容，**Then** 界面明确显示将使用游戏安装目录，新进度可以保存并在重启后读取。
3. **Given** 已启用的适配无法支持当前引擎或运行环境，**When** 玩家启动游戏，**Then** 启动被阻止并说明原因，不悄悄改用其他存档位置或呈现空进度。

4. **Given** 原游戏已有刷新或重新加载入口且已启用兼容，**When** 玩家使用该入口，**Then** 仍使用已确认的存档位置，无需重新选择；重新加载后旧进度可读、新进度可保存，适配未就绪前不得访问存档。

### User Story 2 - 选择两处已有存档并保留恢复副本 (Priority: P1)

当安装目录和资源目录都存在存档时，玩家可以明确选择继续使用哪一处，且原有文件受到保护。

**Why this priority**: 自动选择或覆盖可能导致玩家误以为进度丢失，甚至损失另一份有效进度。

**Independent Test**: 在两个候选目录放入不同的合成进度，分别验证选择、取消、备份失败与恢复流程。

**Acceptance Scenarios**:

1. **Given** 两处均有存档，**When** 玩家首次启用兼容，**Then** 界面列出两个目录及存档文件名、修改时间，要求明确选择；即使文件相同也不自动替玩家选择，不以修改时间推断进度优劣。
2. **Given** 玩家尚未确认选择，**When** 玩家取消或关闭，**Then** 不写入存档、不启用新设置，保留最后有效配置。
3. **Given** 玩家选择了一处已有存档，**When** 首次应用该选择，**Then** 在游戏可能写入之前完成该处受支持存档文件的独立备份；后续读写使用选定目录，另一处保持不变，不复制覆盖或自动合并两处数据。
4. **Given** 备份失败、源文件在确认前变化或目标目录不可写，**When** 玩家应用选择，**Then** 操作失败并保留原文件与最后有效配置，说明可重试的原因。
5. **Given** 已有兼容前备份且游戏停止，**When** 玩家按恢复说明还原，**Then** 可恢复该次适配前的存档；恢复前也须保留当前进度，不覆盖唯一副本。

6. **Given** 原游戏提供清档操作，**When** 玩家取消原确认流程或操作前备份失败，**Then** 不删除或重置任何存档，不报告清档成功。
7. **Given** 玩家通过游戏原有流程明确触发清档，**When** 清档前备份完成且操作成功，**Then** 仅按原功能范围清除或重置所选目录的存档，未选目录和其他游戏不变；刷新或重启后不会误报存档丢失，玩家能够保存新进度。
8. **Given** 清档过程中出错或中断，**When** 玩家再次启动，**Then** 明确提示操作未完成，保留清档前备份并提供恢复步骤，不把部分清档当成成功或自动清理剩余存档。

### User Story 3 - 同类游戏复用且普通游戏保持原有行为 (Priority: P2)

玩家添加另一款使用受支持引擎的游戏时，可以复用相同存档兼容能力；其他游戏不受影响。

**Why this priority**: 解决一类跨平台目录问题，避免回到单款游戏专属启动器。

**Independent Test**: 两个不同配置的受支持样本与一个普通 Electron 合成应用分别启动，检查存档归属和原有初始化行为。

**Acceptance Scenarios**:

1. **Given** 两款不同配置且已识别的受支持游戏，**When** 分别保存与重启，**Then** 各自只读写选定的存档目录，不共享进度或备份。
2. **Given** 未启用存档兼容的既有游戏或不属于受支持范围的游戏，**When** 使用原有启动流程，**Then** 原始入口、初始化、启动参数与既有数据目录策略保持不变，不注入存档兼容行为。
3. **Given** 游戏正在启动或运行，**When** 玩家尝试更改存档位置、关闭兼容或恢复存档，**Then** 操作被阻止，提示先停止游戏。

### Edge Cases

- 只有资源目录有存档时：展示该位置，要求确认后继续使用；不静默搬到安装目录。
- 两处文件集合不完整或内容损坏时：不跨目录拼接或修复，明确报告可检测的异常；加载失败不得被当成空存档并自动覆盖原文件。
- 已选目录消失、被替换、权限变化或出现新的候选存档时：启动前重新核对；目录变化或新冲突需重新确认，不自动回退。
- 名称含空格、日文或中文的路径须可使用；不同游戏解析到相同存档目录时须阻止启用，避免混写。
- 中断、备份失败与配置写入失败须保留可恢复原件；未完成确认不得被记录为适配成功。
- 必须区分玩家经原游戏流程触发的清档与读取失败后的自动重置；后者仍须阻止。合法清档不应在下次启动时被误判为意外丢失。
- 刷新/重新加载前后仍受相同存档保护；旧页面的就绪状态不能使新页面提前读写，失败不得静默使用其他目录。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 识别已支持的引擎及其存档目录规则；首期范围为经验证的 Tyrano 文件存档模式，不以游戏名称、个人路径或仅有 `.sav` 扩展名认定支持。
- **FR-002**: 系统 MUST 为已识别游戏提供明确的存档兼容启用状态与实际目录显示；旧配置缺少该设置时保持未启用，不自动切换既有游戏的数据位置。设置面板须解释开关对读写位置的作用，并分别展示当前已保存的完整目录和本次选择保存后生效的目录；未启用时说明由游戏自行决定，不猜测实际位置。
- **FR-003**: 系统 MUST 使已启用且已验证的适配使用同一选定目录读取和写入文件存档，保留原始游戏入口、窗口与初始化流程，不持久修改、解包改写或重打包游戏及共享运行环境。
- **FR-004**: 系统 MUST 在首次启用或更换位置前检查安装目录与其 `resources` 目录中的受支持存档集合，展示候选信息；存在旧存档时要求确认，存在两处时要求明确选择，未选择不得应用兼容并启动。
- **FR-005**: 系统 MUST 在首次应用或更换位置、游戏可能写入之前备份选定目录中已有的受支持存档文件；备份保留原内容、原文件名、归属与来源信息，并可按说明恢复，失败不得继续。
- **FR-006**: 系统 MUST 保留未选目录中的数据，不自动合并、删除、搬移或覆盖任何旧存档；无旧存档时，经确认的新进度默认写入安装目录。玩家明确触发的游戏内清档按 FR-013 执行，不属于自动清理。
- **FR-007**: 系统 MUST 在游戏停止时才允许启用、停用、更换存档位置或恢复；保存后才提交设置，取消与失败保留原有效设置。
- **FR-008**: 系统 MUST 在启动前检查已启用适配的识别结果、目录有效性、冲突及写入条件；不支持、无法确定、备份失败或存档加载失败时明确报错，不静默回退、重置或生成进度覆盖旧文件。
- **FR-009**: 系统 MUST 将存档选择、备份和适配状态归属于单个游戏；不允许不同游戏使用相同的实际存档目录，包括目录别名指向同一位置的情况。
- **FR-010**: 系统 MUST 让同类引擎游戏复用同一兼容能力，通用核心不包含游戏名称或引擎内部规则；普通游戏与未启用游戏的原有启动和数据行为保持兼容。
- **FR-011**: 系统 MUST 提供实际位置、启用状态及失败阶段的诊断信息，不把存档内容、私人目录或真实游戏资料加入公开交付物。
- **FR-012**: 系统 MUST 提供停用与恢复说明；停用只影响后续启动，不删除备份或自动迁移数据，并提醒原始引擎行为可能读取不同位置。

- **FR-013**: 系统 MUST 保留游戏已有的清空、删除或重置存档功能及其原确认流程，不新增原游戏没有的清档入口。玩家明确触发后，操作前必须完成可恢复备份，只处理所选目录中原功能涉及的受支持存档；取消或备份失败不执行清档，成功后允许正常创建和续读新进度；清档失败或中断必须报告并保留恢复材料，不影响未选目录及其他游戏。
- **FR-014**: 系统 MUST 保留游戏原有的刷新及重新加载功能，不要求玩家关闭兼容或重新选择目录。每次加载仍须在首个存档访问前建立保护，成功后可以继续读写同一位置；接入失败不得以无保护页面继续，不能把禁用刷新/重载当成兼容完成。

### Key Entities

- **游戏存档策略**：所属游戏、已识别引擎范围、启用状态、经确认的实际存档位置；与 Electron 默认数据目录分别表达。
- **存档候选集合**：一个候选目录内属于该游戏且受支持的存档文件集合，包含文件名与修改时间；选择以整个集合为单位，不自动跨目录混合。
- **存档备份**：所属游戏、源目录、备份时间、文件清单与原始内容，独立于游戏后续保存，可用于还原；含首次启用/位置变更前备份及玩家清档前的恢复副本。

### Compatibility & Data Safety *(mandatory)*

- 既有能力包括游戏库、独立配置、自动识别和匹配运行环境、原始应用入口启动、独立 Electron 数据目录与配置恢复。本需求仅新增受支持引擎的文件存档适配，不以文件存档取代 Electron 数据目录，也不取消运行环境与已有数据的兼容检查。
- 对引擎已有的存档来源标识校验，明确选择并完成备份表示确认该集合；可同步当前游戏的单个浏览器来源标识，使其与确认备份一致，不改写存档内标识、不清空 Electron 数据或禁用原校验。当前文件来源与备份不同且原浏览器标识也不匹配时，须重新确认，不能自动接纳。
- 上一 Feature 中“不注入引擎兼容代码”的行为，在本 Feature 中仅对玩家明确启用且经过验证的存档适配开放例外；其他游戏仍维持原有行为。历史规格不作为本次已实现的声明。
- 共享能力负责配置、启动和状态；引擎存档规则属于明确的适配边界。延续现有技术与交付方式，不复制启动器或预建插件平台。
- 备份与恢复先保护原件；配置恢复不得间接把存档选择切换到未经核对的位置，下一次启动仍须检查。存档路径适配不构成对未知游戏的文件系统沙箱。
- 自动化回归使用仓库自有合成应用和合成存档。真实样本验证只能使用经授权的隔离副本；游戏包、真实存档、截图和个人路径不得进入公开文档、测试夹具或 Git 历史。
- 本文定义功能要求；实际实现、真实隔离验收与运行环境组合的证据见 [validation.md](validation.md)。不能由规格文字推断未知游戏也已通过。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少两款不同配置的受支持游戏在隔离副本中均完成“读取旧进度—保存新进度—退出—重启续读”闭环，所选目录与界面显示一致。
- **SC-002**: 两处均有旧存档的测试中，未确认选择时启动写入次数为 0；确认任一目录后，未选目录所有文件内容保持不变。
- **SC-003**: 首次应用、备份失败、配置写入失败、取消、目录变化和加载失败场景均保留原存档；每份成功备份按说明恢复后，内容与备份前一致。
- **SC-004**: 普通游戏与未启用游戏的回归中，原有启动、初始化和数据位置全部保持原行为；两个已启用游戏之间不存在存档或备份串用。
- **SC-005**: 玩家在启用确认及后续游戏详情中均能查看实际存档位置；全部适配失败场景均显示原因，不能以无提示的新进度代替旧进度。

- **SC-006**: 对具备相应原功能的受支持样本，清档取消或备份失败时存档内容 100% 不变；清档成功后刷新及重启均可创建、保存和续读新进度，未选目录与其他游戏内容不变；中断场景可从操作前备份恢复完整受影响集合。
- **SC-007**: 对具备原刷新/重载入口的受支持样本，分别完成“加载旧进度—刷新/重载—保存新进度—再次加载”的闭环；每次页面加载均验证保护先于存档访问，旧页面消息和接入故障不能放行未保护读写。

## Assumptions

- 玩家使用已具备合法来源的完整游戏发行目录，并已提供可匹配的 macOS 游戏运行环境；本需求不新增运行环境下载。
- 首期只支持经验证的 Tyrano 文件存档规则和两处候选目录；其他引擎、自定义文件格式、浏览器存储或独立插件存储不自动纳入支持范围。
- 选择资源目录意味着继续在该目录读写，不为统一目录而复制旧存档；默认安装目录仅适用于确认后的空存档场景。
- 清档、刷新及重载仅保留原游戏已有功能，不扩展为通用存档管理器；支持声明须包含这些功能的回归证据。
- 用户已确认采用按引擎复用的适配方案；具体识别证据、兼容接入时机及运行环境支持组合在规划阶段验证，不预先宣称所有 Tyrano 版本可用。

### Non-Goals

- 不修改游戏包、共享 Electron 或其他游戏；不伪造操作系统平台、不全局重定向文件访问。
- 不自动比较剧情进度优劣、合并存档、修复损坏存档、转换 Windows 存档格式或承诺跨平台必然兼容。
- 不构建通用存档管理中心、云同步、自动周期备份或任意目录选择器；不恢复已移除的单款游戏专属功能。
