# Quickstart & Validation: 引擎存档路径兼容

本文件描述已实现功能的操作与隔离验证步骤；实际执行结果与限制见 [validation.md](validation.md)，不能将步骤本身当作通过证据。

## 1. 准备

- 使用单独测试根与仓库自有合成应用；先执行原有基线回归，确认普通游戏行为。
- 两种自备 macOS Electron 分别验证：7.1.2、26.6.10；通过 LAUNCHER_ELECTRON 指定 Electron.app 或可执行文件，不能只靠系统 Node 验证旧 API。
- 本 Feature 不下载运行环境、不自动导入真实游戏或存档。真实验收仅在用户明确授权的隔离副本中进行，正式安装目录和玩家数据不作为测试输入。
- 合成夹具自行构造两种已支持的引擎存储函数布局、不同 projectID 和路径配置；不复制商业游戏/引擎文件进仓库。

## 2. 既有检查入口

```sh
node tests/core.test.js
ELECTRON_RUN_AS_NODE=1 "$LAUNCHER_ELECTRON" tests/core.test.js
```

第二条要求 LAUNCHER_ELECTRON 指向可执行文件；若是 Electron.app，改为该包内 Contents/MacOS/Electron。

```sh
launcher_save_test=$(mktemp -d /private/tmp/launcher-save-test.XXXXXX)
./启动游戏库.command --library-smoke-test --test-root="$launcher_save_test"
git diff --check
node scripts/audit-publication.js
```

测试根只包含测试创建的数据；不要指向玩家安装目录。图形入口沿用当前隔离检查，已扩展覆盖本 Feature，不编造 npm test/lint 命令。

存档纯逻辑入口：

```sh
node tests/save-policy.test.js
ELECTRON_RUN_AS_NODE=1 "$LAUNCHER_ELECTRON" tests/save-policy.test.js
```

## 3. 必须先通过的接入门槛

1. 原始 main 的路径/主模块/包身份与未启用基线一致，原窗口设置和 preload 初始化标记保留，只有显式启用才添加 main-hook。
2. 在页面首次同步读取及首个可能写入前，路径策略和读写门禁均已安装；不依赖等待 DOM 加载完成。
3. 注入 guard require/语法/安装错误、未知方法定义、提前写入、隔离上下文和自定义 Session 等不支持情形，必须证明没有存档写入。guard 致命失败后下一条页面语句不执行。
4. 存档读取/解码/解析失败后，模拟游戏捕获异常仍尝试保存与删除，必须全部拒绝，原文件摘要不变。
5. 原游戏的刷新/重载每次都在首次访问前重新建立保护，使用当前页面代次 ready；旧页面消息不能放行新页面，进程保持互斥。已失败进程的 poisoned 不能靠刷新解除。
6. 原清档确认取消或操作前备份失败时零删除/重置；成功后刷新及重启可保存新进度；清档中断保留完整操作前副本及未完成记录。
7. 首次适配握手超时、子进程异常、fd 3 继承失败、跨块 JSON 行、就绪前 EOF、EPIPE 和握手伪造消息，均不得标记适配成功；终止完成前保持启动互斥。

单独运行适配门槛：

```sh
node tests/save-hook-smoke.js "$LAUNCHER_ELECTRON"
node tests/save-hook-smoke.js "$LAUNCHER_ELECTRON" --engine-layout
node tests/save-hook-smoke.js "$LAUNCHER_ELECTRON" --legacy-layout
```

直接图形启动若受 macOS 崩溃恢复弹窗干扰，可仅在 `--library-smoke-test` 命令末尾追加 `-ApplePersistenceIgnoreState YES`；测试驱动也只为测试子进程追加这对参数，不改全局偏好。失败门槛必须以退出码 1 结束，信号崩溃不算通过。

分别在两种 Electron 执行，不通过的组合明确不支持，不能靠修改游戏权限、平台值或引擎包绕过门槛。

## 4. 自动化故障矩阵

| 主题 | 必须覆盖 |
| --- | --- |
| 识别与集合 | 正常/冲突/未知 profile，动态配置，未知存储键，超限，损坏格式，日文/中文及空格路径 |
| 候选选择 | 仅根目录、仅 resources、两处不同、两处相同、两处空、取消；存在文件时必须确认 |
| 路径 | 不存在/无权限/别名/目录替换/符号链接文件/硬链接；跨游戏同一真实目录拒绝 |
| 快照 | 扫描后字节变化且 mtime 不变、集合增减、草稿变化、token 过期、源在复制期间变化 |
| 备份 | open/write/close/fsync/hash/rename/父目录同步失败；完成清单缺失；配置失败保留独立备份 |
| 运行中写入 | 临时文件 write/fsync/close/rename 故障不截断原件；rename 后同步失败报告结果不确定；原清档前备份、pendingClear 和成功后 seenKeys 同步；取消/备份失败零删除，删除/重置/同步/完成记录写入失败可恢复；存在记录写入失败不产生新存档 |
| 配置 | v1 读取零改写、首次升级保留 v1、v2 普通编辑保留策略、未知字段不吞掉、旧配置恢复需重查 |
| 并发 | 保存期间启动、重复保存、恢复交错、运行期间修改；UI 与直接 IPC 均拒绝 |
| 会话 | 首读前生效、损坏后永久禁写、正常续玩不反复确认、未选目录变化触发确认、初始空目录首次保存后异常丢失被拒绝；原刷新/重载逐次保护、旧代次消息失效、清档后新进度与异常丢失区分 |
| UI | 已提交位置与未保存选择区分，失败保留输入，焦点与窄屏，运行环境独立登记仍正常 |

所有断言使用合成进度和隔离目录；不得用测试清理函数删除玩家数据。

## 5. 两个真实样本验收

在授权范围内各复制完整发行目录和所需存档到独立临时位置，确保原件不被应用访问；运行环境匹配其实际版本，不为满足双版本测试强行切换真实游戏版本。

每个样本：记录初始文件摘要 → 启用并选择一处 → 核对完成备份和详情位置 → 读取可辨认的旧进度 → 保存一项可辨认新进度 → 正常退出 → 重启读取该新进度。核对未选集合与正式原件完全未变，恢复备份后内容与启用前一致。具备原清档/刷新/重载功能的样本还须执行这些原操作：先取消、模拟备份失败，再成功清档与保存新进度，刷新/重载及退出重启后续读，最后恢复操作前备份；验证未选集合不变。对原游戏没有的功能如实标记不适用，不新增入口，合成夹具仍须完整覆盖。普通应用与禁用适配另作基线对照。

公开记录仅含样本 A/B、运行环境版本、profile、步骤结果和限制，不含游戏包、真实存档内容、个人路径、截图或账户信息。真实样本未执行则标记未验证，不能用合成测试替代 SC-001。

## 6. 玩家使用流程

游戏停止 → 打开游戏设置 → 检查“存档兼容”的引擎支持状态 → 启用 → 查看两个位置的文件名和修改时间 → 明确选择 → 保存并等待备份与配置成功 → 在详情核对存档位置 → 启动。

有旧存档时不默认替玩家选择；修改时间只供参考。没有旧存档时确认使用安装目录创建新进度。取消不应用，失败不换目录。需要停止适配时停止游戏后关闭开关并保存；提示下次原始引擎可能读取另一份数据，不自动搬移存档。

## 7. 人工恢复与回退

1. 停止游戏并关闭启动器，确认没有其他程序写入同一目录。
2. 保留 library.json、相关 runtime.json、save-state、全部 save-backups 和当前选定集合。用一个新的独立备份目录复制当前文件，不覆盖以前任何副本。
3. 核对备份 manifest 的游戏归属、来源目录、文件清单与 hash；有缺失或校验失败就停止，不靠猜测拼接。
4. 在来源目录的隔离副本中先恢复验证：按文件清单复制备份，现有同名文件先另存。恢复时多出来的该 profile 存档先移入本次恢复专用保留目录，不删除；其他文件完全不动。确认恢复集合与清单一致，禁止删除整个游戏目录再覆盖。
5. 核对设置中仍选定预期位置。恢复操作可能使 SavePresence 与曾产生的新键不一致，必须在正常设置中重新扫描并明确确认，不手工删除状态记录。若有 pendingClear，先核对恢复集合与对应操作前备份一致，再由确认流程标记已恢复并建立新存在记录。先在隔离副本启动确认旧进度，再按同样保护步骤处理正式目录；所有原件和恢复前副本继续保留。
6. “恢复配置”只恢复设置，不恢复存档。回退旧启动器还须保留 v2 配置后显式使用升级前的 v1 原件；不编辑删除策略字段，不移除任何备份。

本需求不新增恢复 UI 或自动恢复服务。发布 README 应加入上述保护原则及恢复说明，原有数据目录/不保证任意游戏兼容的说明保留。

交付要求：启用后保留原游戏已有的清空/删除/重置存档及刷新/重新加载功能，不能通过禁用这些操作宣告兼容。清档沿用原确认流程并先完成操作前备份；刷新/重载继续使用同一已确认目录，重新建立保护。未知或远程页面不获得文件能力，普通未启用游戏仍保持原行为。
