## US3 与原生异常退出修复（T031—T035）

- 自有第二布局在测试副本中参数化为不同 projectID：prototype 风格的 Tyrano 520 删除/重置边界，以及无 removeStorageFile/removeSaveData 的 500 重置边界。两个布局分别在 7.1.2 / 26.6.10 通过首次同步读、原身份、重载、故障拒绝、保存/重启和合法清档后新进度。
- 用户反馈异常退出后核对 macOS 原生报告，确认存在 SIGSEGV，并非全部只是恢复弹窗。原断言仅要求子进程失败，会把原生崩溃误算为受控拒绝；新增 signal 必须为空、退出码必须为 1 的断言，成功复现失败。
- 定位为在 web-contents-created / BrowserWindow 构造回调内立即 app.exit 导致旧版 macOS Electron 原生崩溃。修复为先置进程失败门禁，结束当前回调后退出；所有 IPC 操作同时拒绝已失败进程。两版本故障矩阵均以受控退出结束，初始化后续语句不执行、源存档不变。测试专用恢复偏好仍仅用于防止此前崩溃历史弹窗，不是此次崩溃的修复。
- 新增业务失败断言并修复私有 save-backups / save-state 中间目录的链接逃逸；外部目录零写入。新增按文件名区分的存档槽/快捷存档结构校验，扫描与编码写入均执行，损坏集合不自动初始化覆盖。
- UI 两版本完整回归通过：同一库中顺序启动两种配置样本，分别续读不同进度；独立 projectID、备份 ID 与存在记录，未选集合不变。普通应用初始化、停用、数据绑定、独立运行环境登记、运行互斥及恢复仍通过。
- 普通/明确 null 策略描述逐项一致；普通 stdio 仍仅原三个项并将输出写入原日志，不增加状态管道；继承的私有描述环境被清除。跨游戏实际目录/别名冲突及普通编辑保留策略通过。

## 2026-11-15 缺陷回归：已有 userData 切换存档位置

用户报告样本 B 选择根目录后出现“检测到存档移动”及“启动中止”的原引擎弹窗。定位为 Tyrano 同时校验文件 hash 与 localStorage 来源键；此前新建 userData 的验收漏掉了先从 resources 启动后再切换位置的场景，不能以昨日通过覆盖此缺陷。

- 自有 prototype 夹具增加原来源校验：先用旧浏览器标识启动，再启用含不同标识的根目录集合。修复前 guard 已 ready，但原引擎停止初始化，驱动超时失败，成功复现漏项。
- 修复在核对后的原 init_game 前执行：只有当前文件标识与明确选择时的完成备份一致，才同步该游戏单个 localStorage 来源键；不清空 userData、不重写文件 hash、不禁用原校验。当前文件标识再次变化且与浏览器标识不符时，受控退出并提示重新检查确认。
- 识别与运行时均核对 init_game / getExePath 函数摘要；未知方法拒绝。核心只提供通用 readConfirmed，先校验完整完成备份，再读取受支持键；无对应文件返回 null，越界键拒绝。
- 系统 Node 与 Electron 7 Node 模式的 core / save-policy 检查通过。Tyrano 500/520 自有布局分别在 Electron 7.1.2 / 26.6.10 验证来源绑定、未确认来源拒绝、剧情文件不重写、无关 localStorage 保留、原清档/重载与重启；Electron 7 完整双配置 UI 回归通过。未无依据重复无关图形检查。
- 两个全新授权真实副本：先不启用适配从 resources 正常启动，保留同一 userData，再确认根目录并启用；均读回根目录旧系统进度，样本 B 加载旧剧情槽并核对场景，随后原引擎保存新进度、退出重启及两代页面重载均通过。切换读取时剧情存档文件摘要不变；适配启用后的未选集合及正式原件全部摘要不变。
- 第一次真实验证错误地要求原游戏正常初始化也不能更新 SF 文件，因此断言失败；确认仅原系统设置发生正常写入、剧情文件未变后，改为核对原系统进度、剧情文件与未选集合，在全新副本完整重跑通过。未修改正式数据以满足断言。
