# Electron 版本管理与发行目录识别

日期：2026-11-17。来源：用户反馈重复运行环境、嵌套发行目录识别失败，并要求按版本从官方安装。沿用 CommonJS / Node 12、原有 IPC、配置和 C 界面，不改变历史 Feature 的原始范围。

回流日期：2026-11-18。本 Feature 在 001/002 基础上新增官方按需安装，并明确修订受管游戏的退出策略及版本探针期限；历史规格和已完成任务保留，不追溯改写为当时已经支持这些行为。当前实现尚在工作树，不能把它归入已经发布的提交。

## 用户行为与验收

1. 同一可执行文件、精确版本、架构、平台及指纹重复登记时复用原 ID，不新增记录或库 revision。不同版本或程序不原位覆盖。已有重复记录合并显示，但保留所有旧 ID 与游戏绑定，避免破坏数据归属。
2. 版本列表显示 Electron 版本、架构、关联游戏；无关联时如实说明。安装路径通过原生可展开控件查看，不再堆叠重复路径。
3. 识别 resources/app.asar 与未归档的 resources/app。外层是启动壳时，可查找唯一下一层发行目录；多个候选要求明确选择，不递归猜测任意深度。版本证据仍只来自精确声明或随附 PE；PE 元数据有 64 MiB 上限，不执行 Windows 程序，不解析玩家存档。
4. 游戏设置识别出精确版本但未登记时显示“从官网安装匹配版本”；点击后自动选择该版本/架构的 macOS 官方包，无手选版本或任意 URL。下载按需发生，不在浏览目录时后台下载。
5. 仅使用 Electron 官方 GitHub Release 及 HTTPS 跳转，核对官方清单中唯一目标包的 SHA-256，校验归档路径，解包到私有暂存目录，实际版本/架构探针通过后完成安装与登记。无网络、版本不可用、校验/探针失败保持原配置及其他版本，报告原因。
6. 首次启动实测新版 Electron 的版本检查可超过 20 秒，探针等待上限为 60 秒，安装过程中的检查同样可以取消；不因此改变游戏存档适配的握手期限。缓存位于 .launcher/runtimes，按精确版本/架构复用；完整缓存仍核对指纹和实际版本，不因新增游戏复制整份运行环境。游戏 userData、存档备份和运行数据身份继续单独隔离；不能自动把已有数据换到不兼容版本。
7. 安装期间沿用后端单操作锁，禁止保存/恢复/启动交错；界面显示下载、校验、解包与探针阶段。下载时以实际接收字节显示百分比、已下载/总大小和当前速度；服务端无总大小时使用不确定进度，不伪造百分比。校验清单和发行包分别显示，下载达到 100% 不代表安装完成。提供可通过鼠标和键盘操作的“取消下载”，非下载阶段显示“取消安装”；取消请求不受安装互斥锁阻拦，检查、校验、解包和探针阶段同样可取消。先结束本次子进程，再清理本次暂存文件，不登记不完整版本、不再发送本次进度，取消后可重新下载。登记独立生效，游戏设置须另行保存；取消设置不卸载共享版本。

同版本的不同本地程序不要求合并；去重依据是同一份程序及其完整身份，不以版本号相同就删除或重绑旧记录。列表合并仅用于展示相同路径及身份的重复记录，不证明文件当前可用；实际使用前仍须探针复核。

## 恢复与非目标

安装失败只清理本次创建的暂存目录，不删除旧运行环境或游戏目录；配置提交失败保留完成安装，下次可复用。已登记 ID 不批量删除或合并，不改写现有运行数据绑定。

清理失败须如实提示：不能遮蔽原安装错误或声称已全部清理；安装已完成但暂存清理失败时保留完成版本，允许重试登记并复用。取消与清理失败均须释放本次安装状态；不自动扫描删除其他暂存目录。

不新增通用 Python/venv 工具、运行环境升级策略、自动卸载、第三方镜像、游戏包下载、引擎转换或新构建系统。管理器首次启动仍需自备 Electron；识别成功不等于任意游戏的原生模块或 macOS 运行兼容性通过。

官方机制依据：[Electron 安装说明](https://www.electronjs.org/docs/latest/tutorial/installation)。验证证据见 validation.md。

## 2026-11-18 退出后的操作恢复

用户反馈关闭新游戏后，添加、版本管理、启动与设置按钮保持禁用。查明受影响应用沿用 macOS 的关窗常驻语义，原退出按钮也只关闭窗口，进程实际上未结束。

从启动器管理的游戏会话在所有窗口关闭后须请求正常退出；保留原 close / before-quit / will-quit 回调、异步保存和原 main/preload/窗口权限，不改写游戏包或伪造平台。还有其他窗口时不提前退出；游戏自身阻止退出时继续保持运行锁，不能为解锁界面而越过保存或强制结束。

该策略由 adapters/electron-lifecycle.js 固定主进程模块表达，对未启用文件存档兼容的游戏同样生效，是本次明确的生命周期行为修订。文件存档适配仍为单独开关；正常 stdio、cwd、userData 和身份绑定保持原机制。Runner 继续只在实际 child close 后解锁，不以窗口数直接放开配置写入。

验收包含：原 macOS 夹具关窗后进程仍在、单窗口正常退出、多窗口保留、延迟退出保存回调，以及退出后四个入口恢复。实际用户存档不作为回归输入。

## 本次确认与旧规格的关系

- 2026-11-18 用户确认：**所有受管游戏统一**采用全部窗口关闭后请求正常退出的规则。覆盖 002 的 US3 场景 2、FR-010、SC-004 及 plan 中“普通游戏启动参数和行为完全不变”的相关约束，仅限固定生命周期模块与关窗退出行为；不扩大文件存档兼容的启用范围。原入口、初始化、权限和数据位置继续保留。
- 2026-11-18 用户确认：**登记、保存配置、启动前的版本检查统一最多等待 60 秒**，覆盖 002 plan 中版本探针 10 秒的约束；存档适配握手仍为 10 秒，不允许借此延长无保护的存档访问。
- 用户已要求从官方获取匹配版本，覆盖 001“运行环境下载为非目标”和 002“本需求不新增下载”的历史范围限制。自动选择版本，点击安装才开始下载；不静默下载，不替换已有不兼容数据绑定。
- 不删除既有游戏库、独立配置、本地登记、备份恢复、原始入口或存档保护功能。重复条目的视觉折叠不等于删除记录；ASAR/符号链接清理修复不构成新的用户清理功能。
