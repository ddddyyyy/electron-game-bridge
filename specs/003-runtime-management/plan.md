# Plan: Electron 版本管理与发行目录识别

日期：2026-11-18。按用户要求补齐的 Flow-Back 计划，描述当前已确认方案，并非重新设计或重新生成 001/002。功能边界和确认记录见 [spec.md](spec.md)，既有证据见 [validation.md](validation.md)。

## 技术与数据边界

- 保持 JavaScript/CommonJS、Node 12、现有 Electron、Node 标准库及原生 HTML/CSS/DOM；无新包依赖或构建系统。macOS 安装使用系统 curl、unzip 和 ditto，通过参数数组调用，不使用 shell 拼接。
- 复用 `.launcher/library.json`、store 的 revision/token、Runner、固定 IPC 和操作锁。不新增配置 schema；登记可返回 savedRuntimeId。按规范程序路径、版本、架构、平台和可执行文件指纹复用已有记录，旧 ID 不批量迁移。
- 完成缓存为 `.launcher/runtimes/electron-<version>-darwin-<arch>`，同需求共享；每游戏 userData、存档策略、备份和数据绑定保持独立。下载缓存不是游戏存档迁移，不能消除原运行环境身份兼容检查。
- 仅处理 Electron 的精确版本与 x64/arm64 官方 macOS 包。管理器首次启动仍依赖已有 Electron；没有第三方镜像、升级器、自动卸载、断点续传或任意 URL 输入。

## 模块及调用路径

| 落点 | 职责与约束 |
| --- | --- |
| `adapters/index.js`、`adapters/windows-electron.js` | 原入口解析扩展至 resources/app.asar、resources/app 和唯一下一层发行目录；外层最多 128 项，多候选拒绝并要求选择实际子目录。版本证据仍为精确声明或随附 PE，.rdata 上限 64 MiB、随附 EXE 最多 8 个；未知或冲突拒绝，不运行 Windows 程序 |
| `core/config.js` | 相同完整身份重复登记返回原 ID，不写配置或递增 revision；身份不可原位修改，畸形旧记录不参与复用 |
| `core/runtime-manager.js` | 从后端识别需求构造固定官方 Release URL；负责下载、校验、解包、实际探针、完成改名、复用及取消，不判断游戏名称或引擎内部存档规则 |
| `core/launch.js` | 共享 inspectRuntime 以私有探针目录核对实际版本、架构和可执行文件指纹，等待上限统一 60 秒；Runner 仍等待实际 child close 释放锁。removeTree 使用 lstat 且不跟随链接，Electron 下只在清理边界使用 original-fs，将 ASAR 视为物理文件 |
| `library-main.js`、`library-preload.js` | 保留来源窗口/URL 校验与固定操作白名单；主进程重新计算需求，检查 revision/token，安装后独立登记；不得信任前端传入版本、下载 URL 或安装路径 |
| `adapters/electron-lifecycle.js` | 固定 --require 模块位于原入口前；window-all-closed 后延后一轮复核窗口数，再调用正常 app.quit。作用于所有受管游戏，包括关闭存档兼容的游戏；保留游戏原退出回调及其阻止退出的权利，不强杀游戏 |

安装链路：游戏设置识别缺失版本 → 点击安装 → `installGameRuntime({game, revision, token})` → 后端重算 requirement → 安装器 → store.saveRuntime → 返回新快照及 savedRuntimeId → 用户另行保存游戏。安装与游戏设置提交分开；外部配置冲突时不覆盖配置，完成缓存可保留后重试。

`cancelRuntimeInstall` 是固定取消操作，仍校验请求来源，但不受安装单操作锁阻拦。`launcher:runtime-progress` 仅返回阶段、版本/架构及传输统计；不开放任意进程、文件系统或 shell 能力。

## 安装与失败恢复

1. 目标完成缓存存在时先检查目录边界、安装清单、实际探针和可执行文件指纹；不匹配则拒绝覆盖。复用检查不代表重新验证缓存中每个资源文件。
2. 本次安装创建私有随机 `.install-*`，通过 HTTPS 下载官方 SHASUMS256.txt 与唯一目标 zip，校验清单目标唯一及 SHA-256。清单限 1 MiB，zip 限 1 GiB；连接限 20 秒、单次 curl 下载限 600 秒，失败可重试一次，不承诺整体固定时长。
3. 解包前核对归档路径，拒绝绝对路径、上跳或反斜线；用 ditto 解包至本次暂存目录，确认实际程序仍在解包目录内。实际版本/架构/平台探针通过后写 installation.json，再改名为完成缓存；未完成目录不登记。
4. 取消设置本次取消标志，当前安装子进程先 SIGTERM，1 秒未退出再 SIGKILL，等待退出后清理本次暂存目录。哈希及探针也响应取消；停止计时器和后续事件，不强制结束用户游戏。允许重新发起，不恢复部分下载。
5. 清理仅针对本次拥有的暂存目录和探针目录，不批量扫除旧文件。清理失败附加到原失败信息；若安装已完成则保留完成缓存并提示重试登记。无论清理结果如何均释放安装状态；配置提交失败也保留可复用缓存。

## 页面与交互

- 沿用暖白/森林绿 C 界面、游戏卡片、下方详情和同窗口设置，不新增页面体系。
- “Electron 版本管理”按路径及完整身份折叠旧重复记录，列出版本、架构及关联游戏；原生 details/summary 展开安装位置。本地路径登记入口保留，折叠不删除记录，也不把不同目录的同版本副本视为同一程序。
- 游戏设置的版本由程序识别；只有精确需求缺少已登记匹配时显示“从官网安装匹配版本”。浏览目录不后台下载，不增加版本选择器。
- 安装卡片放在禁用字段组之外，显示连接、下载、校验、解包、探针或复用检查。每 500 ms 读取实际下载字节并计算差量速度；总量只取最终 HTTP 200 的唯一合法 Content-Length，未知时显示不确定进度及已接收量。清单与 zip 分别计量，100% 只表示当前文件传输完成。
- 取消按钮在传输时为“取消下载”，其他阶段为“取消安装”；发起后显示取消中并等待后端结果。安装时阻止设置保存、恢复和游戏启动交错；取消入口始终可操作。键盘焦点进入安装卡片，焦点循环跳过继承禁用项，结束后返回下载或重新识别入口；进度通过现有无障碍状态区域更新。
- 正常退出后，四个入口仅依据实际进程结束恢复。游戏阻止退出时继续显示处理中；不设置假超时解锁，不以窗口数直接放开写入。
